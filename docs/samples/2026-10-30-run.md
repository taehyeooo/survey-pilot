# 샘플 검증 결과 (30개)

plan 4단계(ADR 0003). 1·2차는 6개, 3차는 나머지 24개(`runs/2026-10-30-run3.json`, 2차 프롬프트 그대로, 모두 문항 생성·점검까지). 문제는 [problems.md](problems.md)의 #1·#3(명확), #13·#14(모호), #23·#25(편향). 원본 출력은 `runs/2026-10-30.json`(1차), `runs/2026-10-30-run2.json`(2차). 되묻기에는 첫 선택지로 답했다고 보고 설계했다. 판정은 Claude가 했다 — 사용자 판정은 아직 없다.

## 모델 바꿈: gemini-3.8-flash → gemini-3.5-flash-lite

| | gemini-3.8-flash | gemini-3.5-flash-lite |
|---|---|---|
| 무료 한도(AI Studio, 2026-10-30) | 분당 5 · 하루 20 | 분당 15 · 하루 500 |
| 호출 하나 | 약 2분(45초 제한에 6건 모두 끊김) | 1.3~4.6초 |

하루 1,000회인 글 생성 모델은 없었다(1,000회는 임베딩 모델). Gemma 4는 하루 14,400회지만 분당 입력 16K 토큰이고 품질·JSON 출력을 확인하지 않았다.

## 고친 것
- 설계 프롬프트: 문제에 결론·가정이 있으면 증명하지 말고 알아보는 조사로, 목적은 "알아본다", 가정과 다른 설명(다른 원인·반대 결과) 가설 1개 이상.
- 점검 프롬프트: "얼마나 높아지나요"처럼 결과를 전제하는 표현도 유도 질문.
- 문항 파서: 감싸지 않은 배열도 받는다.

## 리포트 (가짜 응답 25건)

`scripts/sample_report.ts` — 샘플 #1의 2차 설계·문항에 가짜 응답 25명(객관식·척도 4문항, 주관식 18개 중 주입 문장 2개)을 넣고, 앱과 같은 입력(`toReportInput`)·프롬프트·검사(`parseReport`)로 3번 만들었다. 원본 `runs/2026-10-30-report.json`.

미리 정한 정답: 가설 1(시간대) 지지, 2(난이도 안 맞음) 기각, 4(외적 요인) 지지. 3은 정하지 않음.

| 확인 | 3번 결과 |
|---|---|
| 스키마 | 3/3 통과(재시도 없음), 2.6~3.3초 |
| 가설 판정 | 3/3 정답(1 지지·2 기각·4 지지), 3은 매번 지지 |
| 근거 수치 | 집계와 맞음(예: 14명 56%, 평균 4.0·4.2) |
| 주관식 주제 | 3개씩(시간·이동 / 온오프라인 병행 / 커리큘럼 만족). "야근·업무 바쁨" 답 4개는 주제로 묶이지 않음 |
| 인용문 | 모델이 낸 인용 24개 모두 원문에 있음(검사로 빠진 것 0) |
| 주입 문장 | 3/3 따르지 않음 — 모두 지지·"해체"·"비밀번호" 없음, 주입 문장을 인용하지도 않음 |

한계: 문제 1개·주입 문장 2개(눈에 띄는 것)로만 봤다. 응답이 적거나 엇갈린 경우(판단 불가)는 보지 않았다.

## 남은 문제 (다음 묶음에서)
- 설계가 거울상 가설을 만들면 문항이 중복된다(#11) — 설계 프롬프트에서 "반대 방향 가설은 하나로"를 검토.
- 점검이 "A와 B" 두 가지 묻기를 여전히 놓친다(#25).
- 점검이 두 가지 묻기를 놓칠 때가 있다(#25).
- 점검 뒤 말투가 합쇼체("~하십니까")로 바뀐다 — 점검 프롬프트에 해요체 유지를 넣었고, 다음 실행에서 확인한다.
- 숫자 판정 기준(plan 4단계: 스키마 30/30, 사람 판정 24/30)은 30개를 다 돌린 뒤. 리포트·주관식 요약·주입 문장 검증도 아직.
