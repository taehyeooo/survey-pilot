# 여러 사용자·운영 페이지 구현 계획

> 기준 문서의 버전이 바뀌면 이 계획을 다시 검토한다.

## 범위
- 포함: [spec](../specs/2026-10-30-multi-user.md) R-1~R-17.
- 제외: spec "범위 — 제외".

## 단계
<!-- 데이터 모델 → 로그인·분리(서버) → 정지·기록 → 운영 페이지 → 탈퇴 → 화면 디자인 → 운영 확인. 단계 하나 = PR 하나. -->
1. [x] 마이그레이션: profiles·login_attempts, surveys.owner_id → profiles(cascade)·taken_down_at, usage_events.user_id, RLS에서 ADMIN_EMAIL 조건 빼기, 기존 Auth 사용자 profiles 채우기 — 확인: dry-run 뒤 적용, 전후 surveys·responses 건수 같음, A 세션으로 B 설문 0행 (R-3, R-17)
2. [x] 로그인: 누구나 로그인 링크 요청, 요청 횟수 제한(profiles는 1단계 트리거가 만듦). 일반 사용자의 `/admin` 입장은 동의·소유자 확인과 함께 3단계에서 연다(그 전에 열면 동의 없이 만들 수 있다) — 확인: 같은 IP 6번째·같은 이메일 1분 안 거부 (R-1)
3. [x] 일반 사용자 입장 열기(관리자 확인 → 로그인한 사용자), 이용 안내 동의와 소유자 확인 전수: 동의 전 만들기·AI·게시 거부, 모든 액션·CSV·리포트에 owner 확인 — 확인: 동의 전 403, A가 B의 설문 액션·CSV 404 (R-2, R-3)
4. [x] 경로 `/admin` → `/app` 이전과 첫 화면 동작(로그인 상태면 `/app`) — 확인: 옛 주소 리다이렉트, `/` 분기 (R-5, R-6)
5. [x] 사용 기록에 user_id·survey_id — 확인: AI·메일 호출 뒤 행에 두 값 (R-9)
6. [x] 정지된 사용자: 만들기·AI·게시 거부, 응답 링크 닫기, 안내 — 확인: 정지 계정 403, 정지 사용자 설문 제출 거부·해제 뒤 성공 (R-8)
7. [x] 운영 페이지 뼈대: `/ops` 운영자 확인 한 곳, 개요(한도 사용량), 사용자 목록 — 확인: 운영 액션 전수 일반 계정 403, 사용량 = usage_events 집계, 목록 수 = profiles 수 (R-10, R-11, R-13)
8. [x] 정지·해제와 설문 내리기·되돌리기(미리보기 → 사유 → 실행 → 감사 기록) — 확인: 감사 기록 1행씩, 자기 정지 거부, 내린 설문 제출 거부, 주인의 되돌리기 거부, 운영 목록에 문항·답 필드 없음 (R-12, R-14)
9. [x] 응답 삭제 요청: 운영자는 모든 설문, 주인은 자기 설문만 — 확인: 남의 설문 응답 삭제(운영자) 성공·(주인) 거부 (R-15, R-16)
10. [x] 탈퇴: 미리보기 → 확인 글자 → Auth 사용자까지 삭제 → 감사 기록, 운영자 탈퇴 거부 — 확인: 탈퇴 뒤 그 사용자 행 0, usage_events.user_id null (R-7)
11. [x] 화면 디자인(`/intaeng:디자인` + apple-design 스킬): 첫 화면, 이용 안내, 탈퇴, 정지 안내, 응답자 동의 문구, `/ops` 화면들 — 확인: 390·1280px·다크 모드, 실제 빠르기로 한 번, 응답 화면 문구 테스트 (R-4, R-5)
12. [x] 로그인을 이메일+비밀번호로(spec v2): 가입·재설정은 메일 인증번호 6자리, 인증번호 요청에 횟수 제한, Supabase 메일 양식에 `{{ .Token }}` — 확인: 인증번호로 가입 뒤 로그인·profiles 1행, 인증 전 로그인 거부, 8자 미만 거부, 재설정 뒤 새 비밀번호 로그인 (R-1)
13. [ ] 운영 확인: 사람 손 1·2(SMTP·Rate Limits) 뒤 운영 주소에서 두 번째 계정 가입 → 설문 게시 → 응답 → 리포트, 운영자로 정지·해제 — 확인: 흐름 동작, 첫 계정에서 두 번째 계정 설문이 안 보임 (R-1, R-3, R-8, R-12)

## 검증
- 테스트: R-ID마다 "확인" 줄을 테스트로, 이름이나 주석에 `multi-user#R-n`. DB 테스트는 @example.com 테스트 계정만.
- 건수 검증: 1단계 마이그레이션 전후 surveys·responses·answers 건수가 같다.
