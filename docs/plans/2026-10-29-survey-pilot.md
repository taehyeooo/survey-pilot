# 서베이 파일럿 구현 계획

> 기준 문서의 버전이 바뀌면 이 계획을 다시 검토한다.

## 범위
- 포함: [spec](../specs/2026-10-29-survey-pilot.md) R-1~R-32 전체. 기반(스키마·접근 제어·한도)과 AI 샘플 검증을 화면보다 먼저.
- 제외: spec "하지 않을 것".
- 4일이 모자라면 미루는 순서: R-26(삭제 요청 화면 — 그동안 SQL로 처리) → R-12(소요 시간 자동 줄이기 — 경고만) → R-15(공유 메시지 편집).

## 단계

단계 하나 = PR 하나를 기본으로 한다. 테스트를 먼저 쓰고, 일부러 망가뜨려 테스트가 잡는지 본다. 테스트에 `survey-pilot#R-n`을 적는다.

### 1일차 — 기반과 샘플 검증
1. [x] 프로젝트 뼈대: Next.js(App Router, TypeScript)·Supabase 클라이언트(서버 전용 service role)·테스트 러너·`.env.example`, Gemini·Gmail mock — 확인: 빈 페이지 빌드, 테스트 1개 통과, 클라이언트 번들에 service key 없음 (R-31)
2. [x] 스키마·RLS 마이그레이션: 10개 테이블, 유일 제약, 응답 후 문항 수정 금지 트리거, 상태 전이 제약 — 확인: anon 전 테이블 select·insert 거부 테스트, 응답 1건 뒤 문항 update 거부 테스트 (R-31, R-14)
3. [x] 한도 가드: `usage_events` 카운터로 Gemini·메일 호출을 감싸는 함수, 스키마 실패 1회 재시도 — 확인: 한도 2 → 3번째 `blocked`, 잘못된 JSON 2회 → 재시도 1회 뒤 실패 (R-27, R-28, R-29)
4. [ ] 샘플 검증(ADR 0003): 사용자 문제 10개 + Claude 초안 20개로 되묻기·설계·생성·점검 프롬프트를 스크립트로 돌려 결과표 작성, 가짜 응답 25건으로 리포트·주관식 요약·주입 문장 확인 — 확인: 스키마 30/30, 모호한 문제에서만 되묻기, 편향 문항 검출, 사람 판정 24/30 이상, 인용문이 원문에 있음, 주입 지시 무시 (R-7, R-8, R-10, R-11, R-23, R-24, R-32)

### 2일차 — 관리자 쪽 설계 흐름
5. [x] 관리자 로그인(매직링크, `ADMIN_EMAIL` 검사)·설문 목록 탭·보관함/복원 — 확인: 다른 이메일 403, 탭별 개수 = DB, 진행 중 보관 → 마감 + 보관, 복원 시 마감 유지 (R-1, R-2, R-5)
6. [x] 문제 입력 → 되묻기 → 설계 제안 → 확인 ① 화면, AI 실패·한도 안내와 다시 시도 — 확인: 입력 1번 → 1행, 확인 전 문항 생성 409, mock 오류 시 상태 유지, 실제 빠르기로 한 번 (R-6, R-7, R-8, R-9, R-28)
7. [x] 문항 생성 → 자동 점검 → 소요 시간 맞추기 → 미리보기·수정·확인 ② (게시 버튼은 8단계) — 확인: 가설마다 문항 ≥1, 마지막 고정 주관식, 소요 시간 단위 테스트, `reviewing` 공개 링크 404, 실제 빠르기로 한 번 (R-10, R-11, R-12, R-13)

### 3일차 — 배포와 응답
8. [x] 게시: slug 링크, 소개글·공유 메시지 복사·편집, 응답 후 수정 제한 화면 — 확인: 메시지에 링크·소요 시간, 응답 1건 뒤 문항 편집 칸 잠김 (R-14, R-15)
9. [x] 응답 화면(Tally 스타일, 모바일 우선)·동의·honeypot·IP 제한·마감/404 안내 — 확인: 동의 없이 400, honeypot DB 0건, 11번째 제출 거부, 상태별 안내 화면 (R-17, R-3, R-4, R-20)
10. [x] 이메일 인증번호(Gmail SMTP, nodemailer): 이미 응답 확인 → 발송 → 확인 → 30분 토큰 — 확인: 11분 뒤 거부, 6번째 시도 거부, 59초 재발송 거부, 메일 한도 1 → 두 번째 거부, 실제 Gmail로 1통 (R-18, R-29)
11. [x] 제출: 서버 검사·한 트랜잭션 저장·`for update`로 목표 도달 마감·접근 시 마감일 확인·수동 마감 — 확인: 대소문자만 다른 이메일 거부, 없는 선택지 400, 목표 3 → 3번째 뒤 closed, 남은 자리 1에 동시 2건 → 1건 성공 (R-19, R-16)

### 4일차 — 결과·리포트·배포
12. [x] 진행 현황·문항별 집계·차트·CSV(BOM, 이메일 없음) — 확인: 응답 N건 → 합계 N·CSV N줄 (R-21, R-22, R-25)
13. [x] 문제 답변 리포트(마감 시 자동·중간 버튼·재사용·참고용)·주관식 주제 묶기·주입 방어 — 확인: 같은 응답 수 두 번 → 호출 1회, 권장 미만 `is_tentative`, 인용문 원문 대조 (R-23, R-24, R-32)

16. [x] Vercel 배포·환경변수·완료 기준 E2E: 실제 문제 1개 → 확인 ①② → 실제 이메일 응답 3건 이상 → 마감 → 리포트 — 확인: 배포 주소에서 흐름 동작, 건수 N = DB N = 리포트 N = CSV N (R-16, R-24)
17. [x] 결과 보고서 화면: 요약 숫자·핵심 문제(AI)·가설별 문항 그래프·주관식 주제 표·다음 행동, 인쇄·PDF — 확인: 리포트 스키마·옛 리포트 다시 채움·화면 데이터 테스트, 로컬 실제 AI로 한 번 (R-33)

## 검증
- 테스트: R-ID마다 "확인" 줄을 테스트로, 이름이나 주석에 `survey-pilot#R-n`. Gemini·Gmail은 mock, 실제 호출은 4·10·16단계에서만(한도 아끼기).
