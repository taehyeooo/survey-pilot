# 0008 커밋 규칙은 훅과 CI에서 같은 스크립트로 강제한다

## 결정
- 규칙
  - 브랜치: `타입/#이슈번호-내용` (예: `feat/#12-login`)
  - 커밋 메시지: `타입: 내용` 한 줄만. 타입은 `feat`·`fix`·`docs`·`style`·`refactor`·`chore`·`perf`·`test`.
  - 본문·트레일러, AI 서명 문구(`Co-Authored-By`, `Generated with` 등), 이모지를 붙이지 않는다.
  - PR 제목도 `타입: 내용`(squash 커밋 제목이 된다), PR 본문에 `Closes #이슈번호`를 넣는다.
- 검사는 스크립트 하나(`scripts/check-commit-msg.sh`)에 두고 두 곳에서 부른다.
  1. 로컬 git 훅(`commit-msg`) — 커밋하는 순간 막는다. `--no-verify`로 건너뛰지 않는다.
  2. PR CI — PR의 모든 커밋 메시지와 PR 제목을 검사한다.
- 규칙을 바꿀 때는 스크립트 테스트 사례부터 더한다.
- CI가 실패한 PR은 머지하지 않는다.
- CI 분량은 작게 유지한다. 무거운 잡(빌드·통합 테스트)은 고친 경로에서만 돌게 한다.

## 이유
- CLAUDE.md는 권고라 AI가 어길 수 있다. 사람이 매번 확인하지 않아도 막혀야 한다.
- 로컬 훅만으로는 부족하다: 클론마다 켜야 하고 건너뛸 수 있다. CI는 건너뛸 수 없다.
- CI만으로는 늦다: 잘못된 커밋을 만든 뒤에야 알아 기록을 다시 써야 한다.
- 스크립트를 하나로 두면 두 곳의 규칙이 어긋나지 않는다.
- 모든 PR에서 무거운 잡을 돌리면 무료 CI 한도를 빨리 쓰고 기다림이 길어진다([0002](0002-cost-zero-free-tiers.md)).

## 비교한 대안
1. AI 도구 훅으로 `git commit` 명령만 검사 — AI가 만든 커밋만 막고 사람·다른 도구의 커밋은 못 막는다.
2. commitlint 같은 패키지 — 규칙이 단순해 셸 스크립트로 충분하고, 의존성이 늘지 않는다.

## 확인 방법
- `scripts/check-commit-msg.sh`(로컬 `commit-msg` 훅과 PR CI에서 실행)와 그 테스트.

## 다시 볼 조건
- 브랜치 보호의 필수 검사를 쓸 수 있으면 이 검사를 머지 필수 조건으로 건다.
- 규칙을 어긴 커밋이 기본 브랜치에 들어가면, 어떤 경로였는지 troubleshooting에 남기고 막는다.
