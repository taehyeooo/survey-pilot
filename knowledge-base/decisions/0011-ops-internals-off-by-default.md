# 0011 운영 내부 정보는 기본 꺼짐

## 결정
"운영 내부 정보"는 서비스 사용자에게는 필요 없지만 공격자에게는 지도가 되는 것들이다 — API 문서, 지표·상태 엔드포인트, 예외 스택, 서버 버전·설정, 개인정보가 섞인 운영 데이터.

1. **기본은 꺼짐.** 운영 환경에서 API 문서·지표 엔드포인트를 켜지 않는다. 켤 때는 환경 변수로만, 이유를 PR에 적는다.
2. **켜도 밖에 열지 않는다.** 지표가 필요하면 서버 안(localhost)에서만 열고 SSH 터널 같은 방법으로 본다.
3. **입구에서 한 번 더 막는다.** 앞단(리버스 프록시·호스팅 라우팅)에서도 그 경로를 막아, 앱 설정 하나를 실수해도 열리지 않게 한다.
4. **운영자가 볼 정보는 관리자 인증 뒤에서만** 내보내고, 개인정보는 가린다.
5. **밖으로 나가는 알림에 내부 정보를 넣지 않는다.** 예외 메시지·스택·개인정보 없이 종류·위치·숫자만. 웹훅 주소는 비밀로 다룬다.
6. **오류 응답에 스택을 넣지 않는다.** 사용자에게는 요청 번호만 주고, 운영자는 그 번호로 로그를 찾는다.

## 이유
- API 구조·지표가 로그인 없이 보이면 공격 표면이 넓어진다.
- 설정 한 줄로 열리는 구조는 언젠가 열린다. 앱과 앞단 두 곳에서 막으면 한쪽 실수가 사고가 되지 않는다.
- 외부 알림 채널은 우리가 지울 수 없는 곳에 남는다. 예외 메시지에는 이메일·주문 번호 같은 값이 섞이기 쉽다.
- 작은 규모에서는 별도 모니터링 서버가 비용과 또 하나의 공개 입구만 늘린다([0002](0002-cost-zero-free-tiers.md)).

## 비교한 대안
1. 운영에도 열어 두고 로그인으로만 보호 — 인증 설정 실수 한 번에 공개된다.
2. 처음부터 별도 모니터링 서버 — 작은 규모에 과하고 지표 서버가 새 입구가 된다.
3. 알림에 예외 메시지를 그대로 — 원인을 빨리 알지만 개인정보가 외부에 남는다.

## 확인 방법
- 사람 리뷰: 배포 설정을 바꾸는 PR에서 운영 프로필의 API 문서·지표 노출과 앞단 차단을 본다. 가능하면 "운영 설정에서 꺼져 있다"는 테스트를 더한다.

## 다시 볼 조건
- 서버가 여러 대가 되어 관리자 화면으로 부족하면 모니터링 도구를 들이되, 여전히 밖에 열지 않는다.
- 외부 개발자에게 API를 공개해야 하면 공개 범위를 따로 정한다.
