# 0007 코드가 기준인 정보는 문서에 복제하지 않는다

## 결정
- 엔드포인트 목록, DB 컬럼 목록, 설정 키 목록처럼 코드가 기준인 정보는 문서에 손으로 옮겨 적지 않는다.
  - 필요하면 코드에서 자동 생성한다(OpenAPI 생성기, 스키마 덤프 등).
  - 문서에는 "어디를 보면 되는지"와 핵심 흐름만 적는다.
- 문서에는 코드에 없는 것을 적는다: 왜 그렇게 했나(ADR), 요구사항(spec), 순서(plan), 원인(troubleshooting).
- 같은 내용을 여러 문서에 쓰지 않는다. 한 곳에 쓰고 나머지는 링크한다.
- 운영 환경에서 자동 생성 문서(API 문서 등)는 기본으로 꺼 둔다([0011](0011-ops-internals-off-by-default.md)).

## 이유
- 손으로 옮긴 목록은 코드가 바뀌는 순간 틀린 정보가 된다. 틀린 문서는 없는 문서보다 해롭다.
- AI는 문서를 믿고 코드를 덜 읽을 수 있어, 낡은 목록이 잘못된 변경으로 이어진다.
- 문서가 "왜"에 집중하면 짧아지고 오래 맞는 말로 남는다.

## 비교한 대안
1. 문서에 목록을 적고 코드를 바꿀 때마다 함께 고치기 — 빠뜨리는 순간이 반드시 온다.
2. 문서 없이 코드만 — "왜"와 요구사항이 사라진다.

## 확인 방법
- 사람 리뷰: 문서 PR에 코드에서 옮겨 적은 목록(엔드포인트·컬럼·설정 키)이 있는지 본다.

## 다시 볼 조건
- 외부 사람이 읽어야 하는 공개 문서(코드를 볼 수 없는 독자)가 생기면, 그 문서는 자동 생성으로 만든다.
