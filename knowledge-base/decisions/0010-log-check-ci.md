# 0010 log.md 검사 — 미갱신 경고, 기존 줄 수정·삭제 실패

## 결정
- `knowledge-base/log.md`는 작업(PR)마다 한 항목을 더하는 append-only 기록이다.
- `scripts/check_log.py`를 PR CI에서 base…head 비교로 돌린다.
  - PR이 log.md를 바꾸지 않았으면 **경고**한다(실패 아님).
  - log.md의 기존 줄을 고치거나 지웠으면 **실패**한다. 틀린 항목은 새 항목으로 정정한다.
  - 새로 더한 줄이 300자를 넘으면 **경고**한다.
- 항목은 짧게 쓴다. 네 칸(한 것 / 확인한 것 / 확인하지 않은 것 / 남긴 지식)에 칸마다 한두 문장만 쓴다.
- 실행한 명령·테스트 개수·스크린숏 같은 긴 확인 내용은 PR 본문에 두고, 항목 제목의 PR 번호로 찾아가게 한다.

## 이유
- 작업 기록을 남기지 않으면 "무엇을 확인했고 무엇을 확인하지 않았나"가 대화와 함께 사라진다.
- 기록을 고칠 수 있으면 나중에 무슨 일이 있었는지 믿을 수 없다. 정정도 새 항목으로 남긴다.
- 미갱신을 실패로 두면 기록할 것이 없는 작은 PR까지 막는다. 그래서 경고만 한다.
- 항목이 길면 log.md가 빨리 커져 아무도 읽지 않는다. 자세한 것은 PR 본문이 맡는다.

## 비교한 대안
1. 미갱신도 실패 — 오타 수정 같은 PR에도 형식적인 항목이 쌓인다.
2. 검사 없이 규칙만 — 갱신을 빠뜨리거나 옛 항목을 고치는 일이 생긴다.
3. 길이 초과도 실패 — 꼭 필요한 긴 줄까지 막는다. 경고로 충분하다.

## 확인 방법
- `scripts/check_log.py`와 그 테스트(PR CI에서 실행). 기존 줄 수정은 실패, 미갱신·긴 줄은 경고.

## 다시 볼 조건
- log.md가 너무 커져 읽기 어려워지면 기간별로 나누는 방법을 검토한다(옛 내용은 고치지 않고 옮기기만).
- 경고를 무시한 PR이 반복되면 미갱신을 실패로 올리는 것을 검토한다.
