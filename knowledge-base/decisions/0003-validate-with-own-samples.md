# 0003 가설·파이프라인은 내 데이터 20~30개로 먼저 검증한다

## 결정
1. 새 가설·AI 파이프라인·데이터 추출은 실제 내 데이터 20~30개 샘플로 로컬 스크립트에서 먼저 검증한다.
2. 쓸 만하다고 확인되면 그때 서비스 구조(API·DB)로 옮긴다.
3. 배포는 로컬에서 안정적으로 동작한 뒤에 한다.
- 검증 결과(샘플 수, 성공·실패 건수, 실패 유형)는 문서로 남긴다.
- 데이터 추출은 건수 검증을 포함한다(원본 N건 → 결과 N건).

## 이유
- 남의 데모나 예제 데이터에서 잘 되던 방법이 내 데이터에서는 안 되는 일이 많다.
- 구조(API·DB·화면)부터 만들면, 가설이 틀렸을 때 버릴 코드가 많아진다.
- 20~30개는 한 사람이 결과를 직접 눈으로 확인할 수 있는 크기이면서, 우연히 맞는 경우를 걸러 낼 만큼은 된다.
- 건수를 맞춰 보지 않으면 조용히 빠진 데이터를 놓친다.

## 비교한 대안
1. 바로 서비스 구조를 만들고 운영 중에 고치기 — 잘못된 가설 위에 구조가 쌓인다.
2. 샘플 몇 개(3~5개)로만 확인 — 실패 유형을 보기에 너무 적다.
3. 수백 개로 처음부터 평가 — 사람이 결과를 다 볼 수 없고 준비 비용이 크다.

## 확인 방법
- 사람 리뷰: 새 파이프라인을 서비스로 옮기는 PR에 샘플 검증 기록(샘플 수·성공·실패·건수 검증)이 링크됐는지 본다.

## 다시 볼 조건
- 데이터 성격상 20~30개로는 실패 유형이 드러나지 않는다는 근거가 생기면 샘플 수를 다시 정한다.
