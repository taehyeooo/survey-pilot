# 0020 누구나 가입하는 여러 사용자 서비스

## 결정
- 누구나 이메일(아이디)·비밀번호로 가입하고, 가입과 비밀번호 재설정은 메일 인증번호 6자리로 확인한다(v2, 2026-10-30 — 이전에는 이메일 링크 로그인). 인증번호 메일은 Supabase가 우리 Gmail SMTP로 보내고, 같은 IP 시간당 5회·같은 이메일 1분 1회로 요청을 제한한다. 로그인 자체는 메일을 보내지 않는다.
- 설문은 `owner_id`로 나눈다. 서버와 RLS 두 곳에서 주인만 읽고 바꾼다([0019](0019-respondents-via-server-only.md) v2).
- 운영 페이지(`/ops`)는 사용자 화면(`/app`)과 따로 두고 `ADMIN_EMAIL`(admins 테이블)만 들어간다. 운영자는 사용자 이메일과 설문 목록·숫자만 보고, 남의 설문 문항·응답·리포트는 보지 않는다. 바꾸는 조치(정지·해제·내리기·되돌리기·응답 삭제)는 [0012](0012-admin-actions-confirm-and-audit.md) 틀로.
- 정지된 사용자의 설문 응답 링크는 닫는다. 운영자가 내린 설문은 운영자만 되돌린다. 알림은 화면 안내만.
- 탈퇴하면 설문·응답·응답자를 즉시 모두 지운다. 사용 기록은 사용자 칸만 비운다. 운영자 계정은 탈퇴·정지할 수 없다.
- 무료 한도(Gemini·메일)는 사람별로 나누지 않고 전체 합으로만 막는다([0018](0018-free-tier-limit-guard.md)).

## 확인 방법
- 테스트: `multi-user#R-3`(남의 설문 0행·404), `multi-user#R-10`(운영 액션 전수 403), `multi-user#R-7`(탈퇴 뒤 0행), `multi-user#R-14`(운영 목록에 문항·답 필드 없음).
- 사람 리뷰: RLS·마이그레이션을 바꾸는 PR, 운영 페이지가 새 테이블을 읽는 PR.

## 이유
- 사용자가 다른 사람도 쓰게 하려고 만든 서비스라고 했다(2026-10-30). 1인용 결정(PRD 결정 2)을 바꾼다.
- 운영자 열람을 목록·숫자로 줄이면 응답자 개인정보를 보는 사람이 설문 주인 한 명으로 남는다.
- 한도를 사람별로 나누지 않은 것은 사용자 선택이다 — 한 사람이 다 쓰면 그날 모두 막히는 위험을 알고, 운영자 정지로 대응한다.

## 비교한 대안
1. 허용한 이메일만 가입 — 남용은 막지만 "누구나 쓰게"와 맞지 않는다.
2. 사람별 하루 한도 — 공정하지만 사용자가 단순한 쪽을 골랐다.
3. Google 로그인 — 메일 한도와 무관하지만 콘솔 설정이 필요하다.
4. 운영자가 내용까지 보기 — 부적절한 설문 판단에 낫지만 응답자 개인정보를 보는 사람이 늘어난다.

## 다시 볼 조건
- 무료 한도가 자주 차서 사용자가 막힐 때(사람별 한도 검토).
- 부적절한 설문을 목록·숫자만으로 판단하기 어려울 때.
- Gmail 발송 계정이 남용으로 막힐 때.
